## 1. 배경

lithent 홍보를 몇 군데 해 본 결과, 라이브러리 소개 글만으로는 사람이 꾸준히 들어오지 않았다.
lithent를 몰라도 쓰고 싶은 도구를 lithent로 만들어 공개하기로 했다(2026-11-23 사용자 결정).
그 도구는 **어느 사이트에나 붙이는 AI 채팅 위젯**이다. 사이트 주인이 `<script>` 한 줄과 태그 하나로
채팅 버블을 띄우고, OpenAI·Gemini·Claude 중 하나에 연결한다.

lithent가 잘하는 것이 그대로 드러나는 주제다. 작은 용량, 남의 페이지에 넣는 Custom Element(`lithent/element`),
Shadow DOM 격리, 스트리밍 응답의 잦은 화면 갱신이 모두 필요하다. README에는 "lithent로 만들었다"를 적는다.

### 사용자 결정 (2026-11-23)

| 결정 | 내용 |
|---|---|
| 저장소 | lithent 저장소가 아닌 새 저장소 `tiny-ai-chat`. 독립 제품으로 이름·README·별을 따로 쌓는다 |

## 2. 사용 장면

1. 개인 블로그·문서 사이트 운영자가 "이 사이트에 대해 물어보세요" 버블을 단다. 시스템 프롬프트에 사이트 소개를 넣는다.
2. 작은 서비스가 고객 문의 앞단에 AI 답변 버블을 단다.
3. 개발자가 자기 백엔드를 이미 갖고 있어서, 문서화된 통신 규약대로 응답하는 엔드포인트를 직접 만들고 위젯만 쓴다.

## 4. 제약과 가정

- 위젯은 남의 페이지에서 돈다. 대상 브라우저는 lithent 위젯 템플릿과 같다(es2020, Safari 14 이상).
- 실제 OpenAI·Gemini·Claude 호출은 사용자의 API 키가 있어야 한다. 자동 테스트는 가짜 제공자로 돈다.
  수동 점검 때 키가 필요하면 세션의 네트워크 비밀(헤더 주입)로 받거나 사용자가 로컬에서 실행한다. 키는 저장소에 넣지 않는다.
- 모델 이름은 자주 바뀐다. 기본 모델을 코드에 박지 않는다(DESIGN DC-6).
- 제공자 SDK와 lithent 버전은 구현 시점의 최신 안정판을 쓴다(2026-11-23 기준 `@anthropic-ai/sdk` 1.12.0,
  `openai` 7.62.0, `@google/genai` 3.6.1, `lithent` 1.26.0, `create-lithent` 0.5.0).
- npm 이름 `tiny-ai-chat`은 2026-11-23에 비어 있음을 확인했다. 첫 발행과 신뢰 발행 설정은 사용자가 한다.
